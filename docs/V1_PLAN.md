# 护肤选购助手 V1 Plan

## Spec

统一入口接收用户问题，先输出一个公开、可审计的 `QueryPlan`：意图、子问题、允许检索的数据源与下一步动作。系统随后仅按计划访问商品、库存和审核资料，最后给出带证据的回答、追问或安全兜底。

V1 仅覆盖基础修护的选购推荐和商品知识问答。它不做诊断、疗效承诺、自动下单、改价、改库存、积分或支付操作。购物车草稿默认关闭；只有显式设置 `ENABLE_CART_DRAFTS=true` 才会生成确认动作。

## Plan

1. **意图与路由**：识别 `recommendation`、`product_knowledge`、`safety`、`clarify` 和 `out_of_scope`。安全和追问分支不得检索或推荐。
2. **复杂问题**：将肤感/诉求、预算/既有使用/避开条件和实时库存拆为公开子问题；由确定性规则选择检索工具。
3. **证据回答与成本控制**：回答只接收审核且在售资料；模型前最多传入 3 条证据、每条最多 240 字，输出最多 300 Token（可通过 `MODEL_MAX_OUTPUT_TOKENS` 下调）。无商品、无库存、无证据、安全或追问分支均不调用模型。
4. **验证**：用 `eval/golden_questions.json` 中的 30 条模拟脱敏真实咨询覆盖问题长短、清晰度、复杂度与噪声；按 `docs/BUSINESS_REVIEW.md` 进行人工标记。
5. **评估数据与试用**：`data/v1_product_master.json` 提供可直接演练的仿真商品主数据；上线前仍须由商品/内容运营与商城后端替换为权威商品、库存和审核资料接口。

## Evidence

- `tests/test_flow.py`：安全、追问、无匹配、证据问答、交易确认开关与工作流节点。
- `tests/test_golden_questions.py`：黄金集的意图、动作和证据契约。
- `GET /api/workflows/mermaid`：导出实际编译后的 LangGraph，而非手写流程图。
- `GET /api/audit-logs`：记录已执行的只读工具、策略决定和结果摘要。
- `GET /api/model-usage-logs`：记录模型调用、实际返回的 Token 用量（如服务商提供）、耗时和零调用/降级原因；不记录 Prompt、资料原文或密钥。

## Done

进入业务试用前，黄金问题集必须通过：每条问题的意图与下一动作符合标注；需要回答的题目仅引用审核证据；安全、模糊和无匹配问题不产生套餐或交易动作。真实试用还需业务确认至少 30 条脱敏问题及其人工标准。
